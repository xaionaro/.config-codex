# Hook gate escape-hatch catalog

This catalog audits the enabled hook decisions in the Codex runtime. ECI is an
accidental-deviation aid, not an adversarial-security system. A gate may stop a
resolved accidental broad, destructive, wrong-target, wrong-owner, or
cross-scope effect. Syntax, punctuation, wrappers, hashes, receipts, and other
metadata are advisory unless they resolve to one of those effects.

Every enabled gate below has a bounded legitimate path. A path with no concrete
effect is transparent and therefore is not a gate.

| Gate family | Stops only this resolved effect | Legitimate path / escape hatch |
| --- | --- | --- |
| Command/planner and environment checks (`ECI_COMMAND_*`, `ECI_PLAN_*`, `ECI_ENVIRONMENT_*`) | A command whose parsed target or effect is concretely unsafe, unresolved at a safety boundary, or an invalid lifecycle identity | Use the ordinary command when its effect is harmless; use the named direct lifecycle, cleanup, or verification route for the affected control operation. Parser uncertainty alone remains transparent. |
| Git destructive/output/context checks (`ECI_BROAD_DESTRUCTIVE_DENIED`, `ECI_GIT_OUTPUT_WRITE_DENIED`, `ECI_GIT_EXECUTION_CONTEXT_DENIED`, `ECI_COMPOUND_MUTATION_DENIED`) | Whole-tree destruction, an actual output-file write, an untrusted execution context, a compound mutation with a concrete broad effect, or an established destructive/selection operation with an unresolved target selector at its documented bounded target boundary. An established expansion may remove every narrowing path from a recognized whole-worktree `git add -A` or admitted `git reset --` only when no path is guaranteed to remain and no established preview, invalid invocation, or alternative selector defeats the broad-effect conclusion. Quoted scalars are one argv word; array-style expansions may yield multiple. Opaque scalar contents, unavailable expansion cardinality, unknown option/action identity, and generic parser uncertainty alone remain advisory. A lone `git reset "$revision"` does not by itself establish a `reset-index` effect. | Name the intended paths or use a non-destructive targeted action. Otherwise narrow the selector/target, keep inspection on stdout, use the trusted executable context, or use the documented bounded coordinator cleanup route. Read-only forms, harmless known value operands, unknown option/action identity, and generic parser/cardinality uncertainty remain advisory. |
| Cross-repository Git checks (`ECI_GIT_CROSS_SCOPE_DENIED`) | A Git mutation targets a repository outside the active session's work repository without a valid declaration, or a worker's Git inspection targets an undeclared repository | The Supervisor or assigned Worker declares one exact canonical, existing repository with `"$HOME/.codex/bin/eci-active" repository-allow-on <canonical-repository> "<reason>"` from that session. The record admits Git mutations there and lets the existing worker inspection, script, and targeted staging routes use that repository. `repository-allow-off` removes it; the record stays bound to the active session and marker CWD. If the recorded target has since disappeared, the Supervisor can revoke it with `repository-allow-off <absolute-path>` only when that path normalizes exactly to the stored repository field and all other record checks still pass. A mismatched path leaves the allowance and active marker untouched; status may continue to report the stale record as invalid until exact revocation. Missing targets cannot be granted or used, undeclared repositories remain denied, and ordinary Producer commits use the resolved repository/effect checks; history-rewriting and explicit ref restrictions stay active. |
| Worker script target (`ECI_WORKER_SCRIPT_TARGET_DENIED`) | A worker would execute a script whose resolved target leaves its assigned provider root and is not in its one declared additional repository | The owning worker declares that exact dependency repository with `"$HOME/.codex/bin/eci-active" repository-allow-on <canonical-repository> "<reason>"`; the same session-bound record then covers the resolved script and worker Git inspection there. Ordinary Producer commits still use the resolved repository/effect checks; this does not lift restrictions on history rewrites or explicit ref mutations. In-root symlink aliases are allowed. |
| Proof, ledger, marker, and live-control targets (`ECI_CROSS_SESSION_ACTIVE_MARKER_DENIED`, `ECI_PROOF_PATH_ESCAPE_DENIED`, `ECI_PLAN_LIVE_CONTROL_DENIED`, `ECI_MARKER_*`, `ECI_LEDGER_*`) | A write resolving to another session's control state, an escaped proof root, or a live marker/ledger/anchor | Use the current session's canonical path and the Supervisor lifecycle route. Ordinary project files and harmless reads remain transparent. Missing or stale historical records are repaired alongside work; they do not block ordinary work. |
| Lifecycle identity and ownership (`ECI_CONTROL_OWNER_REQUIRED`, `ECI_CONTROL_IDENTITY_DENIED`, `ECI_LIFECYCLE_*`, `ECI_COORDINATOR_*`) | A lifecycle/control operation aimed at the wrong provider, session, owner, target, or route | Invoke the canonical `$HOME/.codex/bin/eci-active` route through the Supervisor. Workers may use only the explicit one-repository declaration route above; other lifecycle changes stay Supervisor-owned. The session-scoped 600-second self-edit hatch changes routing only; it does not override Producer ownership or authorize new tracked contributions or Git index/commit operations. Reactivation replaces, never stacks, the window. |
| Worker control and acceptance (`ECI_WORKER_*`) | A worker attempts a resolved Supervisor-only control operation, protected control inspection, denied history/reference/patch mutation, protected target write, unsafe launcher, or a known protected branch/remote ref action | Route protected acceptance/history/ref/remote/patch and lifecycle/control requests to the Supervisor. Ordinary worker commits use the resolved repository/effect checks; workflow rules reserve all new tracked repository contribution checkpoints to assigned Producers and require the exact checked scope. Hook context distinguishes only `coordinator` and `worker`; it cannot verify semantic Producer assignment or staged path/hunk ownership. Amendments, other history changes, explicit ref/remote mutations, and `git apply` remain denied. Read-only ref/remote forms, harmless known value operands, unknown action identity, and generic parser/value uncertainty alone remain advisory. Whole-worktree `-a`/`--all` commits remain denied; inspect staged scope against the assigned contribution. A declared additional repository changes only the repository boundary. |
| Producer checkpoint ownership (`ECI_GIT_COMMIT_PRODUCER_REQUIRED`) | An established Git commit effect from the non-Worker runtime context while an ECI marker is active | Assign every new tracked repository contribution—including documentation, configuration, analysis, and administrative deliverables—to a Producer to author, check, and commit its complete scope; no Supervisor or Orchestrator contribution or commit exception applies. Preserve the actual authorship, exact scope, and provenance of any pre-existing authorized coordinator-written content and hand it to an assigned Producer for integration, checks, and that Producer’s commit. The hook distinguishes only `coordinator` and `worker`; it cannot verify semantic Producer assignment or staged path/hunk ownership. Explicitly authorized Helpers may perform bounded staging/index operations under their responsible Producer’s lookup and agreed order, but Helpers and Worker-context Orchestrators never commit by workflow. Ordinary Producer commits use the concrete repository/effect checks and need no approval artifact or receipt. |
| Commit-time staging (`ECI_GIT_COMMIT_STAGING_DENIED`) | A Git commit selects content outside the prepared index through known path operands, pathspec files, include/only options, or interactive selection, or a known effect-selecting option has an unresolved target at its documented boundary. Known value operands such as `git commit -m "$MESSAGE"` remain allowed. An opaque `git commit -m $message` remains advisory unless source-backed expansion establishes a protected option such as `--amend`; a same-command prefix assignment does not establish that binding. Unknown option identity, opaque scalar contents, unavailable expansion cardinality, and generic parser uncertainty alone remain advisory. The gate does not verify ownership of content already staged. | Preserve the prepared index, make effect-selecting options and targets literal/resolved, inspect the complete staged diff, then make the ordinary Producer commit. Whole-worktree `-a`/`--all` uses a separate broad-effect denial; ownership of already staged content remains a Producer/workflow check. Read-only forms and known value operands remain allowed. Dry-run previews remain read-only. |
| Provider hook installer (`ECI_WORKER_HOOK_INSTALLER_DENIED`) | A worker would mutate the active provider's hook installation/control state through `install-pre-commit-go-mod.sh` | The installer remains Supervisor-owned because it changes provider-wide hook state; the Supervisor invokes it through the canonical installer route. The self-edit hatch changes routing only and does not override Producer ownership of tracked contributions or authorize Git index/commit operations. A dependency-repository script target uses the worker script-target hatch above. |
| Edit-dispatch control ownership (`ECI_EDIT_ROUTE_DENIED`, `ECI_MAIN_THREAD_EDIT_DELEGATION_REQUIRED`, protected-target decisions) | A Supervisor edit of ordinary repository code without a Producer assignment, or a write resolving to protected session control | Assign every new tracked repository contribution to a Producer. The Supervisor may maintain session-local ledgers, plans, status, handoffs, and proof notes outside the tracked repository. The 600-second self-edit hatch changes routing only; it does not override Producer ownership or authorize a new tracked contribution, staging, index mutation, or commit. |
| Stop state (`ECI_STOP_ACTIVE_ECI`, `ECI_STOP_MARKER_*`, `ECI_STOP_REVIEW_VIOLATION_BLOCKED`) | Ending a still-active ECI session or ending with a malformed/ambiguous current marker or an actual failed review | Resume the active task, repair the named current marker, or complete valid normal teardown. Repeated unchanged Stop callbacks are one reminder plus continuation metadata, not a new blocker loop. |
| Review gates (`ECI_REVIEW_*`, `ECI_REVIEW_VERDICT_MALFORMED`) | A malformed current review target/verdict or a required review that found a substantive issue | Correct the named review input, rerun the affected independent review, or return the issue to the implementer. Missing historical evidence is reconciled without denying harmless work. |
| Go module/workspace validation (`GO_*`, `ECI_GO_*`) | A commit or install operation with malformed module/workspace state, unsafe replacement, missing required tool, or wrong destination | Fix the named module/workspace/config/tool/path issue, or use the normal relative replacement and default hook destination. These checks do not gate unrelated commands. |
| Runtime/setup and advisory diagnostics (`ECI_RUNTIME_SYNC_*`, `ECI_TMPDIR_*`, `ECI_HOOK_FAIL_OPEN`, reminders) | No ordinary-work effect; these report stale, unavailable, or failed maintenance context | Continue harmless work and repair the runtime/setup alongside it. A validated provider target may be an empty mount: sync creates missing nested runtime parents beneath that target, while existing aliases/non-directories remain actionable errors. Runtime synchronization is not an authorization ceremony. |

## Escape-hatch contract

- Name the resolved effect and target in every user-facing denial.
- Offer the bounded legitimate route in the same message.
- Preserve the legitimate owner and session; never reroute owner-scoped dependency work merely because a target is a dependency repository.
- Do not require a permission artifact, hash, receipt, generated plan, special punctuation, or canonical spelling for ordinary work.
- If a future gate has no bounded legitimate path, disable that gate until one exists.
- Audit new gates against this catalog and update it in the same change.
