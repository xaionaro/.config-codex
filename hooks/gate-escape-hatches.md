# Hook gate escape-hatch catalog

This catalog audits the enabled hook decisions in the Codex runtime. ECI is an
accidental-deviation aid, not an adversarial-security system. A gate may stop a
resolved accidental broad, destructive, wrong-target, wrong-owner, or
cross-scope effect. Syntax, punctuation, wrappers, hashes, receipts, and other
metadata are advisory unless they resolve to one of those effects.

Every enabled gate below has a bounded legitimate path. A path with no concrete
effect is transparent and therefore is not a gate.

Active ECI Workers use the typed CLI for these native Git families:
`add`, `rm`, `mv`, `restore`, `reset`, `checkout`, `switch`, `commit`,
`update-index`, `read-tree`, `apply`, `merge`, `rebase`, `cherry-pick`, `revert`,
and `am`, plus mutating `worktree` subcommands. Help and preview forms use the
same route. Native `show`, `diff`, `log`, and `bisect` are allowed with any
options. Other concrete Git verbs are native by default; clone acquisition
checks remain separate. Every reachable nested or compound mutation is routed.
Native commands keep their original arguments, environment and repository context.
The effect checks below remain applicable in other contexts.

| Gate family | Stops only this resolved effect | Legitimate path / escape hatch |
| --- | --- | --- |
| Command/planner and environment checks (`ECI_COMMAND_*`, `ECI_PLAN_*`, `ECI_ENVIRONMENT_*`) | A command whose parsed target or effect is concretely unsafe, unresolved at a safety boundary, or an invalid lifecycle identity | Use the ordinary command when its effect is harmless; use the named direct lifecycle, cleanup, or verification route for the affected control operation. Parser uncertainty alone remains transparent. |
| Git destructive/context checks (`ECI_BROAD_DESTRUCTIVE_DENIED`, `ECI_GIT_EXECUTION_CONTEXT_DENIED`, `ECI_COMPOUND_MUTATION_DENIED`) | Whole-tree destruction, an untrusted execution context, a compound mutation with a concrete broad effect, or an established destructive/selection operation with an unresolved target selector at its documented bounded target boundary. An established expansion may remove every narrowing path from a recognized whole-worktree `git add -A` or admitted `git reset --` only when no path is guaranteed to remain and no established preview, invalid invocation, or alternative selector defeats the broad-effect conclusion. Quoted scalars are one argv word; array-style expansions may yield multiple. Opaque scalar contents, unavailable expansion cardinality, unknown option/action identity, and generic parser uncertainty alone remain advisory. A lone `git reset "$revision"` does not by itself establish a `reset-index` effect. | Name the intended paths or use a non-destructive targeted action. Otherwise narrow the selector/target, use the trusted executable context, or use the documented bounded coordinator cleanup route. Read-only forms, harmless known value operands, unknown option/action identity, and generic parser/cardinality uncertainty remain advisory. |
| Cross-repository Git checks (`ECI_GIT_CROSS_SCOPE_DENIED`) | A Git mutation targets a repository outside the active session's work repository without a valid declaration | The Supervisor or assigned Worker declares one exact canonical, existing repository with `"$HOME/.codex/bin/eci-active" repository-allow-on <canonical-repository> "<reason>"` from that session. The record admits Git mutations there and lets the existing script and targeted staging routes use that repository. `repository-allow-off` removes it; the record stays bound to the active session and marker CWD. If the recorded target has since disappeared, the Supervisor can revoke it with `repository-allow-off <absolute-path>` only when that path normalizes exactly to the stored repository field and all other record checks still pass. A mismatched path leaves the allowance and active marker untouched; status may continue to report the stale record as invalid until exact revocation. Missing targets cannot be granted or used, undeclared mutation targets remain denied in these retained checks. Typed Producer commits retain resolved repository/effect checks; Coordinator history and explicit ref restrictions stay active. |
| Worker script target (`ECI_WORKER_SCRIPT_TARGET_DENIED`) | A worker would execute a script whose resolved target leaves its assigned provider root and is not in its one declared additional repository | The owning worker declares that exact dependency repository with `"$HOME/.codex/bin/eci-active" repository-allow-on <canonical-repository> "<reason>"`; the same session-bound record then covers the resolved script there. Typed Producer commits retain resolved repository/effect checks. In-root symlink aliases are allowed. |
| Proof, ledger, marker, and live-control targets (`ECI_CROSS_SESSION_ACTIVE_MARKER_DENIED`, `ECI_PROOF_PATH_ESCAPE_DENIED`, `ECI_PLAN_LIVE_CONTROL_DENIED`, `ECI_MARKER_*`, `ECI_LEDGER_*`) | A write resolving to another session's control state, an escaped proof root, or a live marker/ledger/anchor | Use the current session's canonical path and the Supervisor lifecycle route. A direct Worker `mktemp -d <absolute PREFIX.XXXXXX>` resolves its existing output parent and checks the template against the same protected-control namespace; a reserved template such as `<proof-session>/eci_active.XXXXXX` retains `ECI_CONTROL_OWNER_REQUIRED`. Use an ordinary task-owned temporary-directory template, or route the resolved control-state mutation through the Supervisor. Ordinary project files and harmless reads remain transparent. Missing or stale historical records are repaired alongside work; they do not block ordinary work. |
| Lifecycle identity and ownership (`ECI_CONTROL_OWNER_REQUIRED`, `ECI_CONTROL_IDENTITY_DENIED`, `ECI_LIFECYCLE_*`, `ECI_COORDINATOR_*`) | A lifecycle/control operation aimed at the wrong provider, session, owner, target, or route | Invoke the canonical `$HOME/.codex/bin/eci-active` route through the Supervisor. Workers may use only the explicit one-repository declaration route above; other lifecycle changes stay Supervisor-owned. The session-scoped 600-second self-edit hatch changes routing only; it does not override Producer ownership or authorize new tracked contributions or Git index/commit operations. Reactivation replaces, never stacks, the window. |
| Worker control and acceptance (`ECI_WORKER_*`) | A worker attempts a resolved Supervisor-only control operation, protected control inspection, protected target write, or unsafe launcher. | Route lifecycle and protected control requests to the Supervisor. Native Git family routing is described above; other concrete Git verbs remain native by default. Worker temporary-directory creation and ordinary implementation retain their existing scoped routes. New tracked contribution checkpoints remain assigned-Producer work with exact checked scope, pending intent, fresh same-index lookup and complete staged review. |
| Producer checkpoint ownership (`ECI_GIT_COMMIT_PRODUCER_REQUIRED`) | An established Git commit effect from the non-Worker `coordinator` context while an ECI marker is active | The hook blocks commits from the `coordinator` context only. It cannot distinguish an Orchestrator from a Producer or verify Producer assignment or staged path/hunk ownership. Separately, ECI workflow assigns every new tracked repository contribution—including documentation, configuration, analysis, and administrative deliverables—to a Producer to author, check, and commit its complete scope; Supervisors and Orchestrators author no new tracked contribution and do not commit. Preserve the actual authorship, exact scope, and provenance of pre-existing authorized Supervisor-authored content through an explicit handoff to an assigned Producer for integration, checks, and that Producer’s commit. Explicitly authorized Helpers may perform bounded staging/index operations under their own pending intent and fresh lookup, following their responsible Producer’s agreed order; Helpers never commit. Ordinary Producer commits use the concrete repository/effect checks and need no approval artifact or receipt. |
| Commit-time staging (`ECI_GIT_COMMIT_STAGING_DENIED`) | A Git commit selects content outside the prepared index through known path operands, pathspec files, include/only options, or interactive selection, or a known effect-selecting option has an unresolved target at its documented boundary. Known value operands such as `git commit -m "$MESSAGE"` remain allowed. An opaque `git commit -m $message` remains advisory unless source-backed expansion establishes a protected option such as `--amend`; a same-command prefix assignment does not establish that binding. Unknown option identity, opaque scalar contents, unavailable expansion cardinality, and generic parser uncertainty alone remain advisory. The gate does not verify ownership of content already staged. | Preserve the prepared index, make effect-selecting options and targets literal/resolved, inspect the complete staged diff, then make the ordinary Producer commit. Whole-worktree `-a`/`--all` uses a separate broad-effect denial; ownership of already staged content remains a Producer/workflow check. Read-only forms and known value operands remain allowed. Dry-run previews remain read-only. |
| Provider hook installer (`ECI_WORKER_HOOK_INSTALLER_DENIED`) | A worker would mutate the active provider's hook installation/control state through `install-pre-commit-go-mod.sh` | The Supervisor invokes the canonical installer route for provider-wide hook installation. This operational route does not authorize authoring tracked changes; new tracked repository contributions remain Producer-owned. A dependency-repository script target uses the worker script-target hatch above. |
| Worker Git mutation route (`ECI_WORKER_GIT_OWNERSHIP_DENIED`) | A detected native Worker Git mutation during active ECI uses the dedicated typed route. Native commands outside the routed families remain available with their original options, helpers, output and repository contexts; unknown action identity is advisory. | Use `"$HOME/.codex/bin/eci-worker-git" --repo <repository>` with the named operations below. Literal paths and fixed modes replace Git argument passthrough. The CLI protects observed live hook entries, referents and consumed aliases, proof roots and Git control state; index-only source staging remains available. Follow the worktree restore denial's exact route. When the ancestor's hook relationship remains unresolved, apply the stated owned visibility correction or resolve the named lookup in place, then rerun the identical restore. Move the exact owned ancestor entry to an unused owned name with `mv -- <ancestor> <saved-alias>` only when the fresh CLI check offers that move route, then retry the selected restore; index-only restore remains available. Exact owned disposable native `git init` remains available for fixture setup. Scope ownership, overlap agreement, pending intent, fresh same-index lookup and complete staged-result review remain Producer responsibilities. |
| Producer reset and unsupported index operations (`ECI_WORKER_GIT_OWNERSHIP_DENIED`) | History rewrite, explicit ref transition and arbitrary index metadata are outside the typed Worker API. | Unstage named paths with `eci-worker-git --repo <repository> unstage -- <paths>`; correct committed content through a new prepared-index checkpoint. The supported operations do not replace arbitrary cache or index-metadata manipulation. Preserve unrelated staged content. |
| Edit-dispatch control ownership (`ECI_EDIT_ROUTE_DENIED`, `ECI_MAIN_THREAD_EDIT_DELEGATION_REQUIRED`, protected-target decisions) | A Git operation would remove, relocate, or overwrite the named protected live hook, or a write resolves to protected session control | For the reported effect and target, the responsible Producer edits tracked hook source in place and stages exact owned paths or frozen agreed patches with `eci-worker-git`; index-only unstage uses its named `unstage` operation. The Supervisor uses canonical installer, hook mode, or lifecycle routes for those controls. Do not reroute the same denied destructive Git operation to another role. Assign every new tracked repository contribution to a Producer. Hook context distinguishes only `coordinator` and `worker`; it cannot identify Producer assignment or authorize a general Supervisor code-edit exception. Session-local Supervisor ledgers and proof notes remain outside the tracked repository. |
| Stop state (`ECI_STOP_ACTIVE_ECI`, `ECI_STOP_MARKER_*`, `ECI_STOP_REVIEW_VIOLATION_BLOCKED`) | Ending a still-active ECI session or ending with a malformed/ambiguous current marker or an actual failed review | Resume the active task, repair the named current marker, or complete valid normal teardown. Repeated unchanged Stop callbacks are one reminder plus continuation metadata, not a new blocker loop. |
| Review gates (`ECI_REVIEW_*`, `ECI_REVIEW_VERDICT_MALFORMED`) | A malformed current review target/verdict or a required review that found a substantive issue | Correct the named review input, rerun the affected independent review, or return the issue to the implementer. Missing historical evidence is reconciled without denying harmless work. |
| Go module/workspace validation (`GO_*`, `ECI_GO_*`) | A commit or install operation with malformed module/workspace state, unsafe replacement, missing required tool, or wrong destination | Fix the named module/workspace/config/tool/path issue, or use the normal relative replacement and default hook destination. These checks do not gate unrelated commands. |
| Runtime/setup and advisory diagnostics (`ECI_RUNTIME_SYNC_*`, `ECI_TMPDIR_*`, `ECI_HOOK_FAIL_OPEN`, reminders) | No ordinary-work effect; these report stale, unavailable, or failed maintenance context | Continue harmless work and repair the runtime/setup alongside it. A validated provider target may be an empty mount: sync creates missing nested runtime parents beneath that target, while existing aliases/non-directories remain actionable errors. Runtime synchronization is not an authorization ceremony. |

## Escape-hatch contract

- Name the resolved effect and target in every user-facing denial.
- Offer the bounded legitimate route in the same message.
- Preserve the legitimate owner and session; never reroute owner-scoped dependency work merely because a target is a dependency repository.
- Do not require a permission artifact, hash, receipt, generated plan, special punctuation, or canonical spelling for ordinary work.
- If a future gate has no bounded legitimate path, disable that gate until one exists.
- Audit new gates against this catalog and update it in the same change.

## Typed Worker Git operations

Prefix every operation with `"$HOME/.codex/bin/eci-worker-git" --repo <existing-repository>`. Paths after `--` are literal names, including metacharacters/newlines; absolute paths, empty segments and `.`/`..` escapes are rejected. No arbitrary native Git argv is accepted.

| Operation | Fixed input and effect |
| --- | --- |
| `stage-content -- <files>` | Existing exact file/symlink names to index; no directory/deletion sweep. |
| `stage-removals -- <paths>` | Exact named absent tracked entries staged as removals. |
| `stage-hunks --patch-file <file> -- <paths>` | Frozen patch applied only to index; complete native preview must select only named paths, including rename source/destination. |
| `unstage -- <paths>` | HEAD to named index entries; proven unborn branch removes only named cached entries. |
| `restore --source index\|head\|<full-object-id> --destination worktree\|index\|both -- <paths>` | Explicit source/destination; index source permits worktree only. Submodule worktree recursion is disabled. Worktree restoration refuses existing ancestor symlinks, naming the selected leaf and ancestor. Follow the denial's exact recovery route. For an unresolved hook relationship, apply the stated owned visibility correction or resolve that exact lookup in place, then rerun the identical restore. Move the exact owned ancestor entry to an unused owned name with `mv -- <ancestor> <saved-alias>` only when the fresh CLI check offers that move route, then retry the selected restore. Observed absence of named hooks keeps ordinary owned move/retry available. Index-only restore remains available. |
| `remove --destination index\|worktree\|both -- <paths>` | Explicit state destination; index-only preserves live files. |
| `move -- <source> <destination>` | Two checked endpoints; destination must be absent. |
| `commit --message <text>` | Prepared index only; no path selection, automatic staging or history rewrite. Project validation hooks remain active. |

A typed request does not authorize semantic ownership of already staged content. Producers inspect the complete staged diff/tree and make their own checked append-only handoff commit after fresh same-index coordination. The Supervisor verifies that immutable range. Unsupported native selection modes require an exact supported operation or a separately assigned bounded operational route; no arbitrary-Git wrapper is provided.

Every path is an exact file or symlink leaf; directory and sparse-directory
selection is unsupported. Worktree-affecting gitlinks are rejected because
native operations can alter unnamed administrative metadata. Observed live hook entries, referents and consumed aliases remain protected. An unresolved hook relationship stays advisory for a selected direct file; ancestor movement requires the stated visibility correction and fresh recheck. Configured proof roots' lexical entries, resolved-parent entries and existing referents, and the worktree `.git` pointer retain protection. Proof-root discovery applies only to physical writes; missing roots are supported and unexpected resolution errors name the root. Hunk preview compares complete native index stage records and preserves unrelated conflicts.
