# Hook gate escape-hatch catalog

This catalog audits the enabled hook decisions in the Codex runtime. ECI is an
accidental-deviation aid, not an adversarial-security system. A gate may stop a
resolved accidental broad, destructive, wrong-target, wrong-owner, or
cross-scope effect. Syntax, punctuation, wrappers, hashes, receipts, and other
metadata are advisory unless they resolve to one of those effects.

Every enabled gate below has a bounded legitimate path. A path with no concrete
effect is transparent and therefore is not a gate.

| Gate family | Stops only this resolved effect | Legitimate path / escape hatch |
| --- | --- | --- |
| Command/planner and environment checks (`ECI_COMMAND_*`, `ECI_PLAN_*`, `ECI_ENVIRONMENT_*`) | A command whose parsed target or effect is concretely unsafe, unresolved at a safety boundary, or an invalid lifecycle identity | Use the ordinary command when its effect is harmless; use the named direct lifecycle, cleanup, or verification route for the affected control operation. Parser uncertainty alone remains transparent. |
| Git destructive/output/context checks (`ECI_BROAD_DESTRUCTIVE_DENIED`, `ECI_GIT_OUTPUT_WRITE_DENIED`, `ECI_GIT_EXECUTION_CONTEXT_DENIED`, `ECI_COMPOUND_MUTATION_DENIED`) | Whole-tree destruction, an actual output-file write, an untrusted execution context, or a compound mutation with a concrete broad effect | Narrow the selector/target, keep inspection on stdout, use the trusted executable context, or use the documented bounded coordinator cleanup route. |
| Cross-repository Git checks (`ECI_GIT_CROSS_SCOPE_DENIED`) | A Git mutation targets a repository outside the active session's work repository without a valid declaration, or a worker's Git inspection targets an undeclared repository | The Supervisor or assigned Worker declares one exact canonical, existing repository with `"$HOME/.codex/bin/eci-active" repository-allow-on <canonical-repository> "<reason>"` from that session. The record admits Git mutations there and lets the existing worker inspection, script, and targeted staging routes use that repository. `repository-allow-off` removes it; the record stays bound to the active session and marker CWD. If the recorded target has since disappeared, the Supervisor can revoke it with `repository-allow-off <absolute-path>` only when that path normalizes exactly to the stored repository field and all other record checks still pass. A mismatched path leaves the allowance and active marker untouched; status may continue to report the stale record as invalid until exact revocation. Missing targets cannot be granted or used, undeclared repositories remain denied, and ordinary Producer commits use the resolved repository/effect checks; history-rewriting and explicit ref restrictions stay active. |
| Worker script target (`ECI_WORKER_SCRIPT_TARGET_DENIED`) | A worker would execute a script whose resolved target leaves its assigned provider root and is not in its one declared additional repository | The owning worker declares that exact dependency repository with `"$HOME/.codex/bin/eci-active" repository-allow-on <canonical-repository> "<reason>"`; the same session-bound record then covers the resolved script and worker Git inspection there. Ordinary Producer commits still use the resolved repository/effect checks; this does not lift restrictions on history rewrites or explicit ref mutations. In-root symlink aliases are allowed. |
| Proof, ledger, marker, and live-control targets (`ECI_CROSS_SESSION_ACTIVE_MARKER_DENIED`, `ECI_PROOF_PATH_ESCAPE_DENIED`, `ECI_PLAN_LIVE_CONTROL_DENIED`, `ECI_MARKER_*`, `ECI_LEDGER_*`) | A write resolving to another session's control state, an escaped proof root, or a live marker/ledger/anchor | Use the current session's canonical path and the Supervisor lifecycle route. Ordinary project files and harmless reads remain transparent. Missing or stale historical records are repaired alongside work; they do not block ordinary work. |
| Lifecycle identity and ownership (`ECI_CONTROL_OWNER_REQUIRED`, `ECI_CONTROL_IDENTITY_DENIED`, `ECI_LIFECYCLE_*`, `ECI_COORDINATOR_*`) | A lifecycle/control operation aimed at the wrong provider, session, owner, target, or route | Invoke the canonical `$HOME/.codex/bin/eci-active` route through the Supervisor. Workers may use only the explicit one-repository declaration route above; other lifecycle changes stay Supervisor-owned. A genuine Supervisor repository-code edge case uses the session-scoped 600-second Supervisor self-edit hatch (`coordinator-edit-on`); reactivation replaces, never stacks, the window. |
| Worker control and acceptance (`ECI_WORKER_*`) | A worker attempting Supervisor-only control, acceptance, history rewriting, explicit ref mutation, patch application, protected instructions, or an unsafe launcher | Send protected acceptance/history/ref/patch requests and lifecycle/control requests to the Supervisor. A Worker assigned as Producer makes ordinary scoped checkpoint commits through the resolved repository/effect checks. The hook keeps amendments, other history changes, explicit ref mutations, and `git apply` denied. Whole-worktree automatic staging must be narrowed to exact owned paths or hunks. Runtime metadata exposes only the `coordinator` and `worker` roles, so the hook cannot establish semantic Producer assignment or hunk ownership. A declared additional repository changes only the concrete repository boundary. |
| Producer checkpoint ownership (`ECI_GIT_COMMIT_PRODUCER_REQUIRED`) | The Supervisor or a Job Orchestrator would author a Producer checkpoint | The assigned Producer commits its exact checked scope during handoff. The Supervisor independently verifies the immutable parent-to-commit range; the published Job owner starts dependent review or work only after that verification. No approval artifact or review receipt is required for an ordinary Producer commit. Runtime metadata exposes only the `coordinator` and `worker` roles, so the hook cannot establish semantic Producer assignment or hunk ownership; those remain workflow responsibilities. |
| Commit-time staging (`ECI_GIT_COMMIT_STAGING_DENIED`) | A commit would select or stage content outside the prepared index through path operands, pathspec files, include/only options, or interactive selection | Stage the exact owned paths or hunks separately, inspect the staged diff, and commit the prepared index. Whole-worktree `-a`/`--all` uses the existing broad-effect denial; dry-run previews remain read-only. |
| Provider hook installer (`ECI_WORKER_HOOK_INSTALLER_DENIED`) | A worker would mutate the active provider's hook installation/control state through `install-pre-commit-go-mod.sh` | The installer remains Supervisor-owned because it changes provider-wide hook state; the Supervisor invokes it through the canonical installer route (using the 600-second Supervisor self-edit exception with the `coordinator-edit-on` hatch only for a genuine code-edit edge case). A dependency-repository script target uses the worker script-target hatch above. |
| Edit-dispatch control ownership (`ECI_EDIT_ROUTE_DENIED`, `ECI_MAIN_THREAD_EDIT_DELEGATION_REQUIRED`, protected-target decisions) | A Supervisor edit of ordinary repository code without a Producer assignment, or a write resolving to protected session control | Assign a Producer. For a genuine Supervisor code-edit edge case, activate the 600-second Supervisor self-edit exception. Supervisor-owned ledgers, plans, status, handoffs, and proof notes stay directly editable. |
| Stop state (`ECI_STOP_ACTIVE_ECI`, `ECI_STOP_MARKER_*`, `ECI_STOP_REVIEW_VIOLATION_BLOCKED`) | Ending a still-active ECI session or ending with a malformed/ambiguous current marker or an actual failed review | Resume the active task, repair the named current marker, or complete valid normal teardown. Repeated unchanged Stop callbacks are one reminder plus continuation metadata, not a new blocker loop. |
| Review gates (`ECI_REVIEW_*`, `ECI_REVIEW_VERDICT_MALFORMED`) | A malformed current review target/verdict or a required review that found a substantive issue | Correct the named review input, rerun the affected independent review, or return the issue to the implementer. Missing historical evidence is reconciled without denying harmless work. |
| Go module/workspace validation (`GO_*`, `ECI_GO_*`) | A commit or install operation with malformed module/workspace state, unsafe replacement, missing required tool, or wrong destination | Fix the named module/workspace/config/tool/path issue, or use the normal relative replacement and default hook destination. These checks do not gate unrelated commands. |
| Runtime/setup and advisory diagnostics (`ECI_RUNTIME_SYNC_*`, `ECI_TMPDIR_*`, `ECI_HOOK_FAIL_OPEN`, reminders) | No ordinary-work effect; these report stale, unavailable, or failed maintenance context | Continue harmless work and repair the runtime/setup alongside it. A validated provider target may be an empty mount: sync creates missing nested runtime parents beneath that target, while existing aliases/non-directories remain actionable errors. Runtime synchronization is not an authorization ceremony. |

## Escape-hatch contract

- Name the resolved effect and target in every user-facing denial.
- Offer the bounded legitimate route in the same message.
- Preserve the legitimate owner and session; never reroute owner-scoped dependency work merely because a target is a dependency repository.
- Do not require a permission artifact, hash, receipt, generated plan, special punctuation, or canonical spelling for ordinary work.
- If a future gate has no bounded legitimate path, disable that gate until one exists.
- Audit new gates against this catalog and update it in the same change.
