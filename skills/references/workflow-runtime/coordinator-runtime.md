# Coordinator Runtime

Coordinator/lead only. Ordinary workers load only the local module named in their assignment. This reference owns provider transitions, prompt evidence, model/role admission, required-critic acceptance, nested ECI, and coordinator Git boundaries.

## Admission and agent lifecycle

- Start an outer workflow only when CODEX selects it. A nested ECI remains owned by outer ATE.
- Before a durable spawn, followup, lane-changing message, or write, read [requirement lineage](../requirement-lineage.md); validate the `Lane`, `Assignment`, paths, edges, active requirement state, complete chain, and admission binding. A display `R<n>` needs its bound alias map and is never a bare durable reference. Active admission refs resolve uniquely to active requirements; historical/provenance refs need immutable `state_event_ref` and never authorize work. A failure blocks that provider call without changing status, lane, or lifecycle label.
- Materialize every evidence-bearing prompt/handoff in the proof directory, hash it, record its path and hash in the roster/ledger, and forward both with any dependent evidence. A Critic C Packet 1 omits only serialized lineage and normal review context; its admission, ledger/log-pair check, prompt artifact, and profile checks still happen before spawn.
- `spawn_agent` creates a role; `followup_task` starts a new turn only for an idle reusable role; `send_message` supplies bounded information to a running turn; `interrupt_agent` cancels exact active work only. Never shell-launch agents or close terminal agents.
- Name reusable ordinary producers by stable semantic role. Every blind critic and every special role uses a fresh `spawn_agent({fork_turns:"none"})` with a unique transport name. A `followup_task` never upgrades an ordinary role to special.
- Keep at most one outstanding `wait_agent({timeout_ms:3600000})` per undelivered expected completion. A timeout is non-terminal: do not poll, retry, or infer a crash. Use `list_agents` only for roster maintenance or documented crash recovery.
- Include this exact Stop-hook rule in every subagent prompt: “Follow any Stop-hook prompt in that session, including required proof/checklist files. Fix blockers within assigned scope. Report to the orchestrator only when resolution needs out-of-scope changes, unrelated user work, credentials, or approval.”

## Role and model admission

Every assignment artifact and roster entry has one category and one semantic role. The category-role boundary is canonical compact UTF-8 JSON ending in one LF with ordered fields `{category,semantic_role,authority,required_model_class,artifact_sha256,verdict}`. Its `artifact_sha256` is the SHA-256 after replacing that value with 64 zeroes; `verdict` is `APPROVED`. Reject unknown, missing, reordered, noncanonical, mismatched, or unlisted fields.

| Category | Authority/model | Permitted roles and work |
| --- | --- | --- |
| `exploration-only` | non-authoritative / ordinary | Fact gathering, options, evidence; never authoritative design/admission. |
| `design` | authoritative / special | Designers, design reviewers, ECI Step 2/Critic C, ATE long-term-health reviewers. |
| `mixed` | combined / special | Only explicit `combined fact-and-authority`; never infer it. |
| `implementation` | non-authoritative / ordinary | Implementers, executors, test/QA, Critic A/B, correctness reviewers. |

Normalize stable labels before validation. Unknown labels and cross-field mismatches block the spawn. `sol-high` is an alias, not a model ID: resolve `${CODEX_HOME:-$HOME/.codex}/sol-high.config.toml`, parse only top-level keys, and hash its exact bytes. Its current profile values are `model = "gpt-5.6-sol"`, `model_provider = "openai"`, and `model_reasoning_effort = "high"`; future profile/schema values replace these literals. Immediately before each fresh special spawn record profile path/hash, provider, model, effort, and non-empty `application_route`, then recheck the hash. A changed profile is re-resolved or becomes a model-routing blocker.

Send every exposed selector—currently `model="gpt-5.6-sol"` and `reasoning_effort="high"`. Record unavailable dimensions, including provider binding when the schema cannot expose it, as `unavailable_by_schema`; after an accepted spawn record `requested-special` plus child identity and, absent effective telemetry, `effective-unavailable`. The exact invocation is the only proof of requested selectors; a non-rejecting result proves only child identity. Prompt text, hash, parent defaults, roster, ledger, receipt sidecar, or self-attestation prove neither invocation nor effective application. Omitted/rejected selectors or conflicting telemetry reject that child only; never fall back, reuse, or downgrade. Ordinary assignments record their configured model/provider/exact effort and exposed/unavailable fields without inventing effective values.

### Closed role map

The exact normalized labels are `explorer`→`Explorer`; `researcher`→`researcher`; `brainstormer`→`Brainstormer`; `critic-step2`→`ECI critic-step2`; `critic-A`→`ECI Critic A`; `critic-B`→`ECI Critic B`; `critic-C`→`ECI Critic C`; `e2e-gate`→`E2E gate`; `implementer`→`implementer`; `executor`→`Executor`; `qa`→`QA`; `fdr-reviewer`→`FDR reviewer`; `fdr-meta-reviewer`→`FDR meta-reviewer`; `ate-design-reviewer`→`ATE Design Reviewer`; `ate-meta-reviewer`→`ATE meta-reviewer`; `execution-reviewer-correctness`→`Execution Reviewer: correctness/fidelity`; and `execution-reviewer-long-term-health`→`Execution Reviewer: long-term-health`. Normalize before exact role/category/authority/model validation; unknown labels block.

- `exploration-only` permits only `Explorer`, `researcher`, `fact/issue brainstormer`, `Brainstormer`, `brp primary explorer`, `brp-feasibility-validator`, `loop-breaker`, `repro`, `RCAer`, `Snitch`, `Coordinator`, or `Lead`; each is non-authoritative/ordinary and may gather facts, describe/compare/rank candidate options, and report evidence, but never author or adjudicate authoritative architecture, interfaces, ownership, components, data flow, or admission.
- `design` permits only `Designer`, `Design Reviewer`, `Fundamentals Design Reviewer`, `FDR reviewer`, `FDR meta-reviewer`, `ECI critic-step2`, `ECI Critic C`, `ATE Design Reviewer`, `ATE meta-reviewer`, `authoritative architecture/design`, or `Execution Reviewer: long-term-health`; each is authoritative/special.
- `mixed` is only explicit `combined fact-and-authority`, with `authority=combined` and special model. It may combine fact gathering and authority only when assigned explicitly; never infer it.
- `implementation` permits only `Executor`, `implementer`, `ECI implementer`, `ECI Critic A`, `ECI Critic B`, `Execution Reviewer: correctness/fidelity`, `Test Designer`, `Test Executor`, `Test Reviewer`, `Verifier`, `E2E`, `E2E gate`, or `QA`; each is non-authoritative/ordinary.

An ordinary role assigned authoritative architecture/design or long-term-health review is reclassified with a fresh boundary artifact and fresh special spawn, never an ordinary followup. Special roles always use a fresh unique `spawn_agent({fork_turns:"none"})`; ordinary Explorer, implementer, and ordinary correctness/fidelity slots may be reusable where their outer workflow permits. FDR needs exactly three distinct reports and identities—ordinary fact/issue brainstormer, special reviewer, special meta-reviewer—before a verdict; no reuse, collapse, or simulation.

`PostCompact` is the authoritative compaction refresh signal. Immediately after it, the coordinator/lead re-reads the active outer skill before another decision or tool call. `SessionStart` `startup|resume|clear` is only a best-effort resume/clear reminder. The `PostCompact` hook is read-only; it is a reminder, not proof of rereading.

## Required-critic runtime

The coordinator alone publishes the canonical session manifest through `eci-active manifest-write` while the direct marker is active. The canonical manifest uses schema `eci-required-critics/v2`; worker commits and worker manifest writes are provisional.

Each target has `{target_id,target_kind,diff_artifact,diff_sha256,e2e_required,target_path,target_version}`. The fixed header begins `current_target_id,current_target_kind,current_diff_artifact` and binds canonical repository paths, base/HEAD OIDs, staged/worktree/status hashes, target file hashes, acceptance version, targets, and rows. The canonical row fields are `{target_id,target_kind,diff_artifact,diff_sha256,critic_role,gate_phase,child_identity,spawn_request_artifact,spawn_request_sha256,report_artifact,report_sha256,adjudication_artifact,adjudication_sha256,verdict,e2e_required,e2e_artifact,e2e_sha256,repo_root,git_dir,git_common_dir,base_oid,head_oid,staged_diff_sha256,worktree_diff_sha256,status_sha256,target_path,target_version,intention_artifact,intention_sha256,acceptance_version}`.

At normal `commit`, `final`, and `off`, require exactly fresh A/B/C `postwrite` rows for every governed target plus required E2E. An explicit `prewrite` route instead requires one fresh C `prewrite` row and intention evidence only while that phase/version ledger is empty, with valid `ECI_PREWRITE_WRITER_SESSION` equal to the canonical gate session; Critic C child identity remains separate. It is optional policy evidence, never a universal write firewall, substitute for postwrite A/B/C, or normal acceptance prerequisite. Bind every row to the same target, diff, role, child, and gate-phase tuple. Missing, stale, contradictory, or unverified evidence routes to the exact fresh blind critic and blocks acceptance, commit, final, and clean teardown.

The accepted row set binds live canonical `repo_root`, `git_dir`, `git_common_dir`, target path/version, repository snapshot, and acceptance version. Recompute the trusted diff and target file hashes at acceptance. Reject repository, index, worktree, status, target, path, symlink, or artifact drift. Keep immutable prefix-preserving ledgers at `eci-required-critics.<phase>.<acceptance_version>.ledger`; `Historical phase/version ledgers are evidence for their snapshot`, and a changed snapshot increments the positive canonical acceptance version. `eci-acceptance-anchor` records the append-only session/repository/base lineage.

**Adjudication record details:** An `eci-critic-adjudication/v1` record binds target, role, phase, child identity, and report hash. `APPROVED` maps only to accepted/PASS. A `CONDITIONAL` or `REJECTED` report needs an explicit downgraded record with bounded reason; no matching hash silently erases a report. Every report artifact must be bounded text ending with exactly one canonical `eci_critic_verdict: APPROVED|CONDITIONAL|REJECTED` line. Report text is UTF-8, bounded, LF-terminated, contains substantive text before one terminal marker, and allows only tab/LF controls.

The `Critic C pre-write skip-design admission report` applies only on an explicitly selected skip-design route. It permits that route’s first production write only after fresh special admission. The `Critic C post-write reconciliation report` is separate and governs aggregate acceptance, final proof, and teardown. `nested-accept` is main/coordinator-only under the mutation lock; nested ECI never removes the outer ATE marker.

## Acceptance and Git boundary

Only governed target paths satisfy critic rows; unrelated changes are explicit out-of-scope exclusions. The coordinator publishes/replaces the manifest only through main-owned `eci-active manifest-write <session>/eci-required-critics.json[.source]` under the direct-marker mutation lock. Its source is the exact session destination or directly adjacent `eci-required-critics.json.*` candidate; worker writes, arbitrary paths, shell redirections, and generic file writes are not publication.

`git reset` and mutating `git worktree` remain denied by default. A pre-existing user-provided one-time approval can authorize only its exact canonical `reset|worktree|commit` operation, repository/Git directory, canonical command, reason/timestamp, `authorized_by: user`, and `one_time: true`; the direct commit form has no wrapper, assignment, alias, alternate executable, Git-context option, shell operator, or substitution. The classifier runs before consumption. Approval never fabricates critic evidence, bypasses identity/path/security checks, authorizes unrelated work, or proves human provenance; tracked/indexed artifacts are invalid, and atomic claim directories prevent replay. Do not self-issue approval artifacts.

After validated ECI `off`, atomically publish `eci-teardown-complete` bound to the session, canonical manifest hash, canonical disengage report path/hash, and accepted repository tuple before removing the marker. Replaying with another report or after drift fails closed.

## Exact routing packet contract

Before every spawn, followup, lane-changing `send_message`, or other unbound durable execution, validate and carry: `register_root_id`, `task_root_id`, `lane_id`, `assignment_id`, `derivation_kind`, `predecessor_lane_ids`, canonical executable `requirement_refs`, `derivation_reason`, complete paths and edges with evidence, active requirement-state version, expanded `requirement_chain`, and `admission_binding`. A displayed `R<n>` is never a bare durable ref: it needs the bound alias map. Protocol/review/proof lanes and discovered work need authorized ancestry; a changed owner with unchanged purpose creates a new assignment projection, while a material reroute creates a new lane. Preserve status unchanged on admission failure.

Every prompt states semantic role, category, original requirements when the packet permits them, exact scope/files/ownership, expected output, observable stop condition and false stops, fresh-assignment reread rule, governed-scope admission action, matching skills by exact name, concurrent-edit warning, task-specific likely failure warnings, claim-tag format, and the Stop-hook rule. Reviewer/verifier/QA packets also contain objective/criteria, target/diff, design/contracts when applicable, pre-routing record, admitted style record/deltas/tool evidence, and adversarial scrutiny. For Critic C code Packet 1, materialize and hash the exact diff-only prompt after admission and ledger/log-pair verification, but serialize only role label, required Stop/claim boilerplate, code diff, and reconstruction instruction. Packet 2 carries the full context after `reconstructed intention:` returns.

Prompt artifacts are evidence, not model receipts. The exact spawn invocation proves exposed requested selectors; a non-rejecting result proves child identity; unavailable telemetry remains `effective-unavailable`. Do not infer effective model application from prompt text, a hash, parent defaults, roster, ledger, receipt sidecar, or self-attestation.

## Critic-manifest exactness

The manifest header is ordered `{schema,current_target_id,current_target_kind,current_diff_artifact,current_diff_sha256,current_target_path,repo_root,git_dir,git_common_dir,base_oid,head_oid,staged_diff_sha256,worktree_diff_sha256,status_sha256,target_file_hashes,acceptance_version,targets,rows}`. Paths are absolute lexical-canonical paths with no `..`, duplicate separators, or symlink components; final artifacts are regular non-symlink files. Hashes are lowercase SHA-256. `target_file_hashes` has exactly the governed target-path keys and recomputed values.

Use the trusted current diff matching repository state: `git diff --cached --binary` for staged-only, `git diff --binary` for dirty-only worktree, or `git diff --binary <base_oid> <head_oid>` for clean committed state. Mixed staged/worktree state is a separate snapshot and is rejected unless represented as one. The gate recomputes repository binding at commit/final/off and rejects alternate repository, HEAD/index/worktree/status drift, stale target hashes, targets outside the repository, malformed canonical bytes, duplicate rows, wrong phase, stale child identity, stale diff, missing E2E, or a non-PASS verdict.

At an explicit `prewrite` run, the phase/version ledger must be empty, `ECI_PREWRITE_WRITER_SESSION` must equal the canonical gate session, and exactly C prewrite plus intention evidence is present. Postwrite rows are never replaced by a prewrite row. `commit`, `final`, and `off` require postwrite A/B/C regardless of a prior C prewrite. A new repair or repository snapshot increments acceptance version; a version cannot reset for unchanged snapshot. The bounded `<session>/eci-acceptance-anchor` records session/repository/base lineage and phase/version/manifest/diff/target-set admissions append-only.

Rows are coordinator/session-ledger evidence, not proof a provider child really ran. They prevent stale/omitted/contradictory claims. The coordinator adjudication binds a report marker to its source verdict and bounded downgrade reason; it cannot silently turn `CONDITIONAL`/`REJECTED` into PASS. Manifest publication is only the owned `eci-active manifest-write` route under its mutation lock; shell redirects, arbitrary paths, worker writes, and generic file writes are not substitutes.

### Code-diff and nested boundaries

The optional Critic C prewrite route applies only to selected skip-design work before that route’s first production write. It requires canonical target/snapshot, fresh special Critic C intention, current writer session, and all Packet-1 coordinator checks. It is not a universal worker-write firewall. After write, a separate fresh Critic C reconciles actual scope, approved deltas/deviations, and tool evidence. Long-term-health cannot be downgraded to ordinary correctness/fidelity by alias.

`nested-enter` is valid only under an active direct ECI marker while the canonical mutation lock is held. It records outer owner/session/target; repeated enter is rejected before a prior receipt changes. Only the main/coordinator may publish `nested-accept` or clear it through `nested-exit`; `nested-accept` writes its exact six-line receipt under the owned marker and lock. `nested-exit` validates the receipt at `<session>/ate_nested_eci_completion`, bound to marker, acceptance version, step, and iteration, then clears only its own nested marker. Nested ECI never removes the outer ATE marker; outer final/commit/off consult active nested targets.

## Guarded command and completion behavior

The active command classifier defaults to unknown, not read-only. It recognizes only allowlisted read-only utilities/subcommands, safe `bash|sh|dash|zsh -n <script>` checks, and explicit `hooks/tests` entrypoints. Arbitrary interpreters (including Python), Make, unknown shell scripts, mutating utilities, Git aliases/config/tag/unknown subcommands, substitutions, indirection, malformed input, multiple unsafe markers, unsupported wrapper options, and parser failure are unknown and cannot authorize active acceptance-sensitive writes. It recognizes only bounded `env`/`sudo`/`doas`/`nohup`/`setsid`/`timeout`/`xargs` wrappers and literal `sh -c`/`eval`; `git -c`, `-C`, and `--config-env` are parsed rather than trusted. `ECI_MUTATION_LOCK_HELD` and `ECI_REVIEW_GATE_LOCK_HELD` are not proof: approved callers hold the canonical FD-9 lock or the standalone gate acquires it non-blocking.

Before coordinator completion, independently re-read changed lines, run relevant checks, inspect current diff/status, and verify every original requirement. A worker handoff is an unreviewed PR: no acceptance claim, commit, teardown, or user success statement depends on it until the coordinator verifies it. Preserve unrelated dirty paths as explicit exclusions; never bundle them into a critic target or commit.
